# RuleSet `pint-ae@1.0.4` (PINT AE Billing 1.0.4)

Data and oracle inputs for the validator's only RuleSet. The Rust rules live in
`services/validator-rs/src/rules/`; this directory holds what they are checked against.

## Layout

| Path | Committed | What |
|---|---|---|
| `upstream/SHA256SUMS` | yes | pinned sha256 of every file below under `upstream/` |
| `upstream/rules-base.tsv`, `upstream/rules-ae.tsv` | yes | the 302 official asserts (`id, flag, context, test, message`), extracted from the official `.sch` by the Phase 2 planner; the XPath `test` is the specification of each Rule |
| `upstream/schematron/{trn-invoice,trn-creditnote}/*.xslt` | no (fetched) | official compiled schematron (SaxonC) |
| `upstream/examples/{trn-invoice,trn-creditnote}/*.xml` | no (fetched) | the 30 official examples (27 invoices, 3 credit notes) |
| `upstream/xsd/{maindoc,common}/*.xsd` | no (fetched) | OASIS UBL 2.1 XSD closure (2 maindoc + 13 common) |
| `codelists/codelists.tsv` | yes | `list_id, code` for every XPath-inlined list with at least 5 codes (generated by `conformance/extract_codelists.py`) |
| `coverage/<family>.tsv` | yes | one row per rule, 10 columns (spec 5.2.4); family tasks replace `pending` with `implemented`, `structural` or `upstream_noop` |
| `mutations/<family>.jsonl` | yes | mutation fixtures (empty until the family tasks fill them) |

## Fetching the upstream artefacts (owner decision D-3)

Vendoring OpenPeppol / OASIS files into this public repository waits on the owner's licence check
(D-3). Until then nothing under `upstream/{schematron,examples,xsd}` is committed (see
`upstream/.gitignore`); it is downloaded and verified instead:

    scripts/fetch-upstream.sh            # download, verify against the pinned hashes
    scripts/fetch-upstream.sh --check    # verify only

- `resources.zip` from `https://docs.peppol.eu/poac/ae/pint-ae/resources.zip`, release 2026-07-29,
  sha256 `1e8b0bd595c672ac9d6fc886ddd0eb8027cb39a1d26bebdcb1ada37b7eee491f` (pinned in the script).
- UBL XSDs from `https://docs.oasis-open.org/ubl/os-UBL-2.1/xsd/`, hashes in `upstream/SHA256SUMS`.
- A version string is not enough: upstream hotfixes can land under the same version, so CI runs the
  script and fails on any hash mismatch. Files are never edited after download.
- Offline: `UPSTREAM_ZIP=/path/resources.zip UPSTREAM_XSD_DIR=/path/xsd scripts/fetch-upstream.sh`.
- If the owner approves vendoring, remove the three lines of `upstream/.gitignore` and commit the
  files; `SHA256SUMS` and the CI check stay as they are.

## Revision policy

The RuleSet id is `pint-ae@<spec>+r<N>`; `pint-ae@1.0.4+r1` ships in Phase 2.

`+rN` increases whenever any invoice could get a different set of issue rule ids, paths or
severities: a rule's logic, a code list, a rule added or removed, a status change, a path template
change. Message text (en or ar) and `note` changes do not bump it.

A new upstream release (for example 1.0.5) becomes a new directory `rulesets/pint-ae-1.0.5/` and a
new registry entry; the old directory stays until no deployment serves it. The golden snapshot
`snapshot/r1.jsonl` is never edited: a behaviour change bumps the revision and writes `r2.jsonl`.

## Conformance runners (`services/validator-rs/conformance/`)

Standalone `uv run` scripts with inline metadata (`saxonche==13.0.0`, `lxml==6.1.3`). All take a
directory of XML files and write JSON keyed by the path relative to that directory.

    run_schematron.py <dir> --out saxon.json   # {doc: {kind, failed: {assert id: count}}}
    xsd_check.py      <dir> --out xsd.json     # {doc: {kind, valid, error}}
    compare.py --rust rust.json --saxon saxon.json --xsd xsd.json --allow allowlist.tsv

`rust.json` is `{doc: {rules: {official rule id: count}, errors: int, exported: bool}}`. `compare.py`
exits 1 on any unexplained difference; `allowlist.tsv` has exactly two rows (`ibr-co-14`, `ibr-124`
for `credit_note`, upstream defect 2). Reference results on the 30 official examples: zero failed
asserts, 29/30 XSD-valid (`Volume-discount-credit-note.xml`, upstream defect 3).

Tests: `uv run services/validator-rs/conformance/tests/test_conformance_tools.py` (after fetching).
